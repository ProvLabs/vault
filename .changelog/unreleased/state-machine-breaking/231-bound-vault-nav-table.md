* Bound the per-vault internal NAV table, whose size drives the cost of every total-vault-value calculation. A new `max_vault_nav_entries` param (default 100, max 1000, governance-updatable, `0` meaning the default) caps how many denoms a vault may price; `SetVaultNAV` rejects a new denom once a vault is at the cap, while repricing a denom already in the table stays allowed so an over-cap vault can still be written down. A new `nft/<scope-id>` NAV denom must also name a scope that exists on chain, rather than merely being a well-formed metadata address. Both checks apply to new denoms only, so an entry whose marker or scope is destroyed later can still be repriced. `InitGenesis` imports an entry that breaks either rule with a warning rather than halting, so a chain can always restart from its own export [PR 264](https://github.com/provlabs/vault/pull/264).
