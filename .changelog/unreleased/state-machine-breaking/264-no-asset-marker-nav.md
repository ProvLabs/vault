* Stopped mirroring internal NAV entries into the marker module. `UpdateVaultNAV` previously called the marker keeper directly to set the chain-wide NAV of the denom it priced, attributed to the vault address. Because vault creation is permissionless and the creator is the default NAV authority, and because a vault holds no permission on the markers of the assets it prices, anyone could overwrite the marker NAV of any registered marker, bypassing the access controls `x/marker` enforces on its own NAV messages; the stored `NetAssetValue` carries no source field, so consumers reading marker NAV had no way to tell the write apart from a legitimate one. Internal NAV entries are now written to the vault table only. The vault's own share denom remains the single marker NAV the module publishes, which reconciliation continues to set on the marker the module creates and holds grants on. Setting an internal NAV volume beyond the marker NAV `uint64` range is no longer rejected, since nothing publishes it [PR 264](https://github.com/provlabs/vault/pull/264).
