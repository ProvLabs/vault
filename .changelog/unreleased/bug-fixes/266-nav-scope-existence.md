* Required a metadata value-owner NAV denom (`nft/<scope-id>`) to name a scope that exists on chain, rather than accepting any well-formed metadata address. `SetVaultNAV` and `InitGenesis` now check the metadata module for these denoms, the same way they check the marker module for every other denom, so a typo or a fabricated scope id can no longer be priced into a vault's internal NAV table. The metadata keeper is wired into the vault keeper for the check. A genesis import logs and skips a NAV entry whose denom is no longer registered instead of panicking, so a scope deleted after its price was recorded cannot make a state export unimportable [PR 266](https://github.com/provlabs/vault/pull/266).
