* Stopped mirroring internal NAV entries into the marker module. `UpdateVaultNAV` previously set the chain-wide marker NAV of the denom it priced, so a vault could overwrite the price of any registered marker it holds no permission on, bypassing the access controls `x/marker` enforces on its own NAV messages. Asset prices now stay in the vault's internal table, and the vault's own share denom remains the only marker NAV the module publishes. A NAV volume above the uint64 range is now accepted, since nothing mirrors it into the marker module's uint64 volume [PR 266](https://github.com/provlabs/vault/pull/266).
