* Bound the per-vault internal NAV table, whose size drives the cost of every total-vault-value calculation. A new `max_vault_nav_entries` param (default 100, governance-updatable, `0` meaning the default) caps how many denoms a vault may price; `SetVaultNAV` rejects a new denom once a vault is at the cap, while repricing a denom already in the table stays allowed so an over-cap vault can still be written down. `InitGenesis` enforces the same cap. An `nft/<scope-id>` NAV denom must now name a scope that exists on chain, rather than merely being a well-formed metadata address [PR TODO](https://github.com/provlabs/vault/pull/TODO).
